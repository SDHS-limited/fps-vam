# 성능 QA — 2026-11-02

## 수행

Unity Editor Play Mode와 Profiler를 사용했다. 런타임 QA 컴포넌트가 발사, 시점 회전, Rigidbody 이동 부하, 적 스폰을 자동 실행했다. 각 측정은 5초 준비 후 20초 수집했다. 테스트 컴포넌트는 씬에 저장하지 않았으며 플레이어 빌드에서 제외된다.

이것은 입력 장치 기반 전체 플레이 검증이나 독립 실행 빌드 벤치마크가 아니다. Profiler 및 측정 코드 자체 비용이 포함되며, 실시간 진행과 적 생존 수가 달라 정확한 전후 성능 향상률을 주장할 수 없다.

## 적용한 수정

- 탄환/중앙 조준 RaycastAll을 재사용 NonAlloc 버퍼로 변경. 버퍼가 꽉 차면 확장 후 재검사하여 충돌 누락을 방지한다.
- 탄환 Renderer 목록을 캐시하고 매 충돌/풀 반환 시 배열을 생성하지 않도록 수정했다.
- 매 프레임 적중 로그와 불필요한 컴포넌트 검색을 제거했다.
- 행복도, 수류탄 수, 타이머 텍스트는 표시 값이 바뀔 때만 갱신한다.
- 적 피격 색상은 MaterialPropertyBlock을 사용하여 적별 머티리얼 복제를 방지한다.
- 적 사망의 중복 처리를 막고 플레이어 참조 누락 시 오류를 방지한다.

## 남은 문제

RTX 3060 Laptop GPU / Direct3D12 환경에서 1초대 멈춤이 반복됐다. 보존된 Profiler 프레임 예:

- 프레임 423766: Main Thread 1138.2ms, D3D12 GPU presentation wait 1094.3ms.
- 프레임 424006: Main Thread 1339.5ms, D3D12 GPU presentation wait 1293.5ms.
- 프레임 424684: Main Thread 1324.1ms, D3D12 GPU presentation wait 1277.7ms.

따라서 긴 멈춤의 주된 관측 지점은 GPU/화면 표시 대기다. 이 마커만으로 드라이버, OS, 에디터 표시, GPU 작업 중 어느 것이 근본 원인인지 확정할 수 없다. 평상시 한 프레임의 FrameTimingManager 표본은 CPU 3.7231ms / GPU 3.4980ms였다.

120 FPS 제한은 긴 멈춤을 해결하지 못하여 되돌렸다. 렌더 품질이나 그래픽 API, 프로젝트 설정은 변경하지 않았다.

다음 검증은 동일 장면의 독립 실행 Development Build와 에디터를 비교하고, Direct3D11 실행과 비교하는 것이다. 에디터 그래픽 API 전환에는 재시작이 필요하다. 현재 결과로 QA의 랙 문제가 완전히 해결됐다고 판정할 수 없다.

## 검증과 정리

- 컴파일 및 자동 플레이 중 콘솔 오류 없음.
- 40개 겹친 검사 대상에서 초기 32칸 버퍼를 넘겨도 가장 가까운 충돌을 정확히 선택함 (1.5m).
- Play Mode와 Profiler 종료. 테스트용 오브젝트/체력/적 스폰 변경은 씬에 저장하지 않음.
- 세부 측정은 같은 폴더의 baseline.txt, optimized.txt, optimized-repeat.txt, capped120.txt에 기록.
